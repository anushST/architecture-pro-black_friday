# Задание 9. Выявление и устранение «горячих» шардов

## 1. Коллекция products

|Операция|Источник чтения|Допустимая задержка|Обоснование|
|---|---|---|---|
|Просмотр карточки товара|secondary|1-2 секунды|Пользователь не заметит небольшую задержку в описании|
|Поиск по каталогу|secondary|2-5 секунд|Поиск не критичен к актуальности, важна скорость|
|Проверка остатка при добавлении в корзину|primary|0|Критично — риск продажи недоступного товара|
|Проверка остатка при оформлении заказа|primary|0|Критично — финальная проверка перед списанием|
|Обновление цены (чтение для отображения)|secondary|5-10 секунд|Цена меняется редко, задержка допустима|

**Почему:**
- Операции просмотра не критичны — пользователь может увидеть описание с задержкой
- Операции проверки остатков критичны — иначе продадим то, чего нет в наличии
- Частота обновлений остатков высокая (каждая покупка), но критична только в момент резервирования

## 2. Коллекция orders

|Операция|Источник чтения|Допустимая задержка|Обоснование|
|---|---|---|---|
|Просмотр истории заказов|secondary|2-5 секунд|История не меняется часто, задержка допустима|
|Проверка статуса заказа пользователем|secondary|3-5 секунд|Статус обновляется редко (раз в часы/дни)|
|Получение заказа для обработки (админ)|primary|0|Критично для корректной обработки и избежания дублей|
|Создание заказа (чтение для проверки дублей)|primary|0|Нельзя создать дубль заказа|
|Отчёты и аналитика|secondary|10-30 секунд|Аналитика не требует реалтайм данных|

**Почему:**
- Заказы обновляются редко после создания
- Пользователь не ждёт мгновенного обновления статуса
- Создание и обработка заказов требуют строгой консистентности
- Административные операции не должны работать с устаревшими данными

## 3. Коллекция carts

|Операция|Источник чтения|Допустимая задержка|Обоснование|
|---|---|---|---|
|Получение корзины для отображения|secondary|1-2 секунды|Пользователь может видеть корзину с небольшой задержкой|
|Добавление товара (чтение для обновления)|primary|0|Критично — нельзя потерять товар из-за race condition|
|Удаление товара|primary|0|Критично — избежать конфликтов при параллельных операциях|
|Слияние корзин (гость → пользователь)|primary|0|Критично — нельзя потерять товары при авторизации|
|Оформление заказа (чтение корзины)|primary|0|Критично — финальная операция, требует точных данных|

**Почему:**
- Корзина часто обновляется (добавление/удаление товаров)
- Все операции изменения требуют консистентности
- Только просмотр корзины может допустить минимальную задержку
- При оформлении заказа критично видеть актуальное состояние

## Настройка Read Preference

### Products
Каталог/поиск: secondaryPreferred (fallback на primary если secondary недоступна)
Проверка остатков: primary
Карточка товара: secondaryPreferred

### Orders
История заказов: secondaryPreferred
Статус заказа: secondaryPreferred
Создание/обработка: primary
Аналитика: secondary (можно nearest для географически распределённых систем)

### Carts
Отображение корзины: secondaryPreferred
Все операции изменения: primary (по умолчанию)

## Допустимая задержка репликации

### Общие требования

**Критичные операции (primary only):**
- Задержка: 0 мс
- Используют primary для гарантии актуальности

**Некритичные операции (secondary allowed):**
- Просмотр данных: 1-5 секунд
- Аналитика: 10-30 секунд
- Отчёты: до 1 минуты

### Мониторинг репликации

Настроить алерты:
- Задержка репликации > 5 секунд — warning
- Задержка репликации > 10 секунд — critical
- Secondary отстала > 1 минуты — немедленное вмешательство
